# External texture delivery, 4 November 2026

The production scene requested nine external PNG textures in the founder lift, founder chair, marble, wall and bronze material paths. Build-time lossless WebP now reduces the nine unique representations from 17,693,714 to 8,509,712 bytes. That saves 9,184,002 bytes (51.91% of these textures). The November 3 full-scene Resource Timing capture had ten PNG requests because cream stone was requested twice.

The build keeps a source/output SHA pair for every approved texture. The original PNG serves as the fallback when the source changes, the encoder output changes, the client prefers PNG, or a separate CDN supplies the release. The server includes `Vary: Accept, Accept-Encoding` and revalidates mutable source URLs. Hashed WebP URLs can use immutable caching. `MD_GEOMETRY_STORAGE=0` also disables this optional optimization. A local full build retains verified derivatives between builds, adding 8.51 MB of generated storage.

Each texture passed RGBA parity through two real browser paths on Windows, Chrome 156. An isolated browser decoded the PNG and candidate WebP via `HTMLImageElement` and via `createImageBitmap` with `colorSpaceConversion: 'none'` and `premultiplyAlpha: 'none'`. Each was uploaded to a WebGL2 texture, attached to a framebuffer, read back as RGBA8 and compared channel by channel. All nine image dimensions matched in both paths, with zero differing channels. This includes normals, packed roughness/metalness, color maps and the scalar bronze input. The checked source and encoded digests bind prepared variants to the specific pairs verified in the browser. Evidence is `texture-pixel-parity-2026-11-04.json` in the local visualization evidence directory.

The focused tests check actual generated RGBA values/dimensions, Accept quality exclusions, original PNG selection, WebP selection, both proxy passes and cache policy. `npm run verify:delivery` exercises the negotiated image bodies on the integrated production server along with the existing geometry HTTP checks. Whole-site loading time, frame pacing and mobile-device results belong to the integrated production capture.
